# Accessibility checklist

Inspect semantic landmarks and heading hierarchy, accessible names, labels, errors, status announcements, alt text, link purpose, color contrast, zoom/text resize, reduced motion, visible focus, keyboard order, dialog focus return, and touch target behavior.

Prefer native HTML and test the actual user journey with keyboard-only navigation. Use automated audits and browser accessibility trees to find gaps, then manually verify the fix. Test responsive and error states as well as the default desktop state.
