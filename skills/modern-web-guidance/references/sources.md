# Official sources

Use these for current details instead of copying stale rules into the skill. Treat dates and browser support as time-sensitive, and record the chosen Baseline target in the project's `AGENTS.md` or web documentation.

## Platform and support data

- [Baseline](https://web.dev/baseline): interoperable feature targets ("newly available" and "widely available").
- [MDN Web Docs](https://developer.mozilla.org/en-US/docs/Web): API references and compatibility tables.
- [Can I use](https://caniuse.com/): per-browser support and usage data.
- [Chrome for Developers](https://developer.chrome.com/): platform features, DevTools, and Lighthouse.

## Process and agent guidance

- [Google Chrome Modern Web Guidance 101](https://codelabs.developers.google.com/codelabs/modern-web-guidance-101): choose a Baseline target, establish Lighthouse measurements, prioritize one workstream, implement, and verify.
- [Modern Web Guidance repository](https://github.com/GoogleChrome/modern-web-guidance): agent-oriented web guidance and skill source.
- [Lighthouse](https://developer.chrome.com/docs/lighthouse/overview): automated audits for performance, accessibility, best practices, and SEO.
- [web.dev Learn](https://web.dev/learn): current performance, accessibility, and responsive-design learning paths.

## Standards

- [WCAG 2.2](https://www.w3.org/TR/WCAG22/) and the [ARIA Authoring Practices Guide](https://www.w3.org/WAI/ARIA/apg/).
- [HTML Living Standard](https://html.spec.whatwg.org/).
